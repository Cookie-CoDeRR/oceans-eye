DATA SOURCES (live-tested 2026-11-15 IST)
- OBIS API (https://api.obis.org/v3): keyless, CORS-open.
  - Example verified: Rhincodon typus grid precision 3 -> 840 cells with
    records, 17,375 records in shown cells; 34,541 records in an Indian Ocean
    bbox query (40..100E, -10..25N).
  - Qualification: presence-only observation records, sampling-biased; not
    abundance, absence, or distribution truth.
- NASA JPL MUR SST (jplMURSST41) via NOAA CoastWatch ERDDAP
  (https://coastwatch.pfeg.noaa.gov/erddap): keyless; NOT CORS-open, so the
  app proxies it through /api/* (no upstream browser calls).
  - Verified series at 15.0N, 72.0E: 291 samples, ~30-day stride (30-32 days),
    2003-01-01T09:00Z to 2026-10-29T09:00Z, no duplicate timestamps, SST range
    26.65..31.31 C, 285 of 287 calendar months represented (stride sampling,
    not calendar-month aggregation).
  - Trend on deseasonalized anomalies: +0.21 C/decade (SE +/-0.05),
    Mann-Kendall z = 4.03, lag-1 autocorrelation 0.33 (significance reported
    as indicative only).
  - Field verified: 3,643 cells, 2026-11-13, bbox 8..20N / 68..78E, stride 24.
  - Qualification: 1 km daily Level-4 satellite SST analysis grid (GHRSST MUR v4.1),
    not a direct measurement at each cell. ERDDAP can be slow under load (one 503
    observed); the app shows a visible error state on failure.
- Basemap: (c) OpenStreetMap contributors, raster tiles darkened via CSS.

2026-11-15 ~15:26 IST: /api/cell briefing corrections after review.
- Direction conventions verified at owning docs:
  - Waves: "Wave directions are always reported as the direction the waves
    come from." (https://open-meteo.com/en/docs/marine-weather-api)
  - Ocean current: "Direction following the flow of the current ... where the
    current is heading towards." (same page) - so waves are FROM, current is TO.
  - Wind: meteorological from-convention per NOAA/NWS glossary:
    https://www.weather.gov/cae/weatherterms.html ("Wind Direction: The
    direction from which the wind is blowing.")
  UI labels updated accordingly (was "toward" for waves - fixed).
- Resolutions from source docs: MUR 0.01deg (~1km) analysis grid; Open-Meteo
  marine waves/currents ~0.08deg (~8km) with an explicit "not suitable for
  coastal navigation" note; Open-Meteo weather resolution varies by model.
  Each briefing section now shows the actual sampled grid point returned by
  the upstream (no false shared-cell claim). Weather call passes
  cell_selection=nearest so ocean taps do not silently snap to a land cell.
- Briefing labeled "latest model snapshot, not a time-evolving pattern"
  (user's weather-patterns ask is only a first step here).
- Open-Meteo service terms (https://open-meteo.com/en/terms): free API is
  non-commercial use only, CC-BY 4.0, rate caps 10k/day, 5k/hour, 600/min;
  commercial use requires a paid plan. Noted in README; relevant if the
  project's "clean endpoints for companies" idea ever goes commercial.
- Input validation on /api/cell: finite lat/lon within +/-90 / +/-180;
  upstream calls stay behind the fixed host allowlist with timeouts/cache/
  rate limit as before.
